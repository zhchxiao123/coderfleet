# 平台聊天引用、日期范围与执行过程

日期：2026-11-14（America/Los_Angeles）。

## 现象与复现

用户询问“深入分析一下这周的工作吧”，页面显示“回答引用了本轮未检索的来源”，没有思考或执行过程。

对原运行 `5b2140772be381e92c94ebb88c5a8da7` 只读审计：Task 已完成，实际返回38条活动，原生结构化回答2362字；引用数组使用了7个 Task ID。服务端仅接受片段 ID，导致已有回答整篇丢弃。原日志还包含3个 thinking 块及其增量事件，平台页面此前仅展示最终结构化答案，没有使用已有聊天渲染链路。

原请求日期是单日2026-11-13，MCP未提供日期范围调整工具，所以“这周”仍然只能读单日资料。问题不是模型没有执行或没有生成答案。

## 修复

- 引用支持片段 ID，以及能映射到已读回执的 Task/Conversation ID。未读 ID 不生成链接；未匹配项转为部分回答提醒，保留模型已有答案和已核实来源。
- 新增 select_period MCP 工具，支持周、月和自定义起止日期。catalog 按执行账号时区提供当前时间和本周/上周/本月建议范围。项目授权不扩大；每个日期视图独立缓存，来源加上视图标识，避免切换日期后混用片段。切换后进度使用当前目录指纹核验。
- 平台执行过程复用 ChatLogRenderer 和已认证的 Task SSE。显示真实 SDK 思考及工具调用/结果，过滤结构化输出容器防止重复最终答案。历史按需加载，活动过程实时展开，断线重放重建渲染状态，切换会话/页面关闭旧连接。
