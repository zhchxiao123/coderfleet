# SDK 流式思考重复 · 2026-11-12

SDK 消息可以先包含一个没有可见文字、只有签名的 thinking 块，随后才包含可见的 thinking 块。旧 renderer 按消息 ID 和类型取第一个未完成块；第一个空块没有 DOM 节点，导致匹配失败，又为完整消息创建了第二个气泡。最小用例稳定复现两个气泡；同一实际日志的脱敏事件回放显示三段内容被渲染为六个气泡。

现在只匹配已有可见节点的流式块，优先匹配相同文本，其次匹配累计前缀，再更新原节点。空签名块不会抢占匹配，最终消息仍正常套用 Markdown。按消息 ID 隔离，不用全局文本去重掩盖合法的重复回复。

回归位于 `tests/frontend/claude-sdk-renderer.test.cjs` 的 `empty signed thinking blocks` 用例；它同时断言流式阶段立即可见、完成阶段只有一个气泡，以及完成后的 Markdown。实际脱敏回放为旧版六个、修复后三个气泡。问题依赖事件顺序，文本 grep 无法阻止，因此用行为回归固定。

同轮界面整理将运行设置、参数和会话恢复收入工具栏的单个“更多”入口；默认不展开，也不向每条日志插入操作面板。成功 Hook 的内部事件不占聊天时间线，失败提示保留。桌面与移动端只传入当前 Conversation 的 Task，历史 Task 可按需选择。此次浏览器自动化连接超时，实际视觉布局验收未完成；Node 交互和日志回放不替代浏览器验收。
