# SDK 补充消息读取了错误页面的上传状态

## 影响

桌面端点击补充消息时出现 `uploadingImages is not defined`。错误发生在编辑器读取阶段，没有发出 HTTP 投递请求。移动端恰好定义了该变量，因此共享控制模块的单独测试与移动端路径都没有暴露问题。

## 原因

桌面上传状态位于 state.js 的 `chatUploadingImages`，移动端在 mobile.html 内定义 `uploadingImages`。接入共享 SDK 控制模块时，桌面编辑器回调复制了移动端变量名。已有组件测试自行提供 editor.read，未加载真实桌面状态和调用方，所以覆盖不到回调中的未定义变量。

## 修复与验证

实际加载 state.js、chat.js 和共享 SDK 控制模块，以按钮点击复现零 HTTP 请求和相同错误；修正后同一用例正常投递。共享入口只接收显式的 text/hasAttachments/uploading 数据，不读取页面特有的上传变量。

主发送按钮现在统一派发：SDK 运行中发送文字为补充消息，空输入为原生 interrupt；排队选择、附件和定时沿用 Task 提交路径。桌面与移动端使用同一动作判断，原生提问保持独立的问题卡片。

回归用例从实际桌面脚本和实际 mobile.html 主脚本驱动按钮与键盘事件，验证上传中/连接中不误发、补充不受队列上限影响、显式排队和附件不丢失、未知结果不自动重放、失败保留草稿与相同请求 ID，以及无运行任务时输入能重新启用发送按钮。

## 防止再发

页面适配器显式传入自己的上传布尔值；调用方集成测试不能只用测试自造的 editor.read 代替真实页面状态。发生入口变量或事件绑定变化时，运行 `node --test tests/frontend/claude-sdk-composer.test.cjs`。
