# 流式 Markdown 与后台进度噪声 · 2026-11-12

两个独立渲染路径造成体验问题：SDK delta 分支直接设置 textContent，直到完整 AssistantMessage 才调用 Markdown；system task_progress 则每次追加一个提示。最小回归中，100 条进度加一次启动产生了 101 条多余提示，流式内容没有标题、列表或代码块结构。

正文/thinking 现在使用最终回复相同的 Markdown 解析器，每个动画帧合并一次更新。完整消息同步渲染并移除该块的待刷新记录；流结束或中断时刷新最后内容，避免延迟回调覆盖最终结果。测试直接加载随应用分发的 marked，覆盖分片加粗、列表、未闭合代码围栏、表格及千次 delta 的合并更新。

后台进度不追加对话节点。启动和终态只更新所属工具卡片，保留原生后台 ID、摘要及运行/完成/失败/停止状态；找不到所属卡片的失败提示一次。固定 SDK 的 task_notification 和 task_updated.patch.status 都可报告终态，后者的 killed 映射为停止。启动工具调用成功不等于后台任务完成，后到的启动、非终态更新或工具结果也不能重置已确认的终态。日志重载会清理旧状态并取消未绘制帧，原始事件不受展示过滤影响。

回归：`tests/frontend/claude-sdk-renderer.test.cjs`。这两个问题依赖事件顺序和更新次数，不能用 grep 防止，因此由真实事件分发路径的行为断言约束。
