# 工作与待处理

项目问答仍是默认入口。选择项目后可以直接新建对话、追问或开发；无需先创建卡片或工作流。

## 工作

左侧“工作”将已有项目对话、独立任务、工作流运行和专题集中展示。支持项目及执行中、待处理、待验收、受阻筛选。点击“继续对话”回到原会话，保留上下文；“看板视图”继续使用现有专题看板。

普通对话完成显示“本轮完成”，不会自动要求验收。已有专题明确处于 `review` 时才显示“待验收”。这批视图不新增独立的目标或交付数据库：保留长期交付与版本化检查将分批接入。

## 今日 / 待处理

集中显示需要人工处理的工作：

- 有效的原生/MCP 提问与工具授权，指向真正等待的 Task。
- 工作流人工审批，打开原工作流的运行面板。
- 已有专题的待验收状态，定位原看板卡片。
- 最新执行失败或受阻的工作，回原记录决定如何继续。

较新的排队消息不会覆盖正在等待回答的任务；重试恢复后的旧失败、过期问题和归档记录不计入待处理。计数表示需要处理的工作数，同一工作可以有多条事项。原记录删除后明确提示；专题引用损坏会显示受阻，不自动换一个会话。

切换工作页面不会清掉当前项目会话。桌面和手机各自按会话保留未发送文字，切换对话时不把附件带到其他项目。现有原生提问、插话、中断、排队和历史记录仍走原交互链。

## 手机

手机会话列表顶部“工作”打开同一套工作与待处理视图，支持项目和状态筛选。普通会话与待回答事项直接回到手机聊天；复杂工作流、专题通过明确的目标链接打开相应管理视图。

## CLI 与接口

```bash
coderfleet work list
coderfleet work list --project my-project --view running
coderfleet work inbox
coderfleet work inbox --project my-project --json
coderfleet work list --limit 50 --offset 50
```

HTTP：`GET /api/workbench?project_name=my-project&view=attention&limit=50&offset=0`。`view` 支持 `all`、`attention`、`running`、`review`、`blocked`；响应包含分页、总数、项目列表、计数和原执行引用。未知项目返回 404，无效筛选/分页返回 422。操作者认证与原接口一致，CLI 复用本机凭据/显式远端凭据规则。

该查询不启动任务、不读取完整日志、不探测容器、不调用模型或外部 MCP，不返回控制和审批令牌。归档记录仍通过原历史功能查询。平台助手维持既有范围与权限；它不会因为新增这些视图而接管项目问答。
