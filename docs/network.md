# 网络与代理

## 容器怎么上网

添加账号时「网络」有两个选择：

- **经 relay（推荐）**：容器只加入一个内部网络，自己没有通往外网的路。所有流量经一个中继容器转发到宿主机上的代理。即使 CLI 不认代理设置，它的流量也出不去别的路。
- **直连**：容器走 Docker 默认网络，直接访问外网，不经代理。

构建镜像时走的是 Docker 自己的网络，不经 relay。

## 代理设置

「设置 → 通用 → 高级 → 代理与容器」：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 宿主机代理地址 | `host.docker.internal` | 代理所在的地址 |
| 代理端口 | `7890` | 宿主机代理的 HTTP 端口 |
| 容器时区 | `Asia/Shanghai` | |
| 镜像平台 | `linux/amd64` | Apple 芯片用 `linux/arm64` |
| 镜像名 / 镜像标签 | `coderfleet` / `latest` | |

保存后重启项目生效；改了镜像平台要重新构建镜像。

宿主机代理要打开「允许局域网连接」，否则容器连不上它。

## 其他配置

下面这些没有界面，需要时直接编辑工作区里的 `config.conf`，然后重启项目。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `PROXY_BYPASS` | 空 | 不走代理的域名或网段，逗号分隔 |
| `INTERNAL_SUBNET` | `172.21.0.0/16` | 内部网络的网段，和现有网络冲突时修改 |
| `RELAY_IP` | `172.21.0.2` | 中继容器的地址，要在上面的网段里 |
| `DNS_UPSTREAM` | `https://1.1.1.1/dns-query` | 容器域名解析的上游 |
| `DOCKER_SOCKET` | 关闭 | 设为 `auto` 或具体路径后，所有项目的容器都能使用宿主机的 Docker |

## 数据放在哪里

| 位置 | 内容 |
| --- | --- |
| 工作区（默认 `~/.coderfleet`） | `config.conf`、`accounts.conf`、`projects.conf`、各账号的登录数据 `accounts/`、对话记录 `conversations/` 和 `tasks/`、镜像构建文件 |
| App 数据目录 | 保存的后端连接、本机后端的日志 `backend.log` |
| 系统钥匙串 | 远程后端的访问令牌 |

工作区里的 `docker-compose.yml` 是根据配置自动生成的，不要手工修改。

备份工作区目录就备份了全部账号、项目配置和对话。
