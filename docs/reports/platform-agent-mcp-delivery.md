# 平台助手 MCP 重构交付

日期：2026-11-13（America/Los_Angeles）。

## 已实现

普通查询由 SDK 通过宿主 `fleet` MCP 检索 CoderFleet 的公开聊天和 Task；初始提示只含当前消息、范围和历史回复指针。创建查询只冻结元数据、原问题和日志字节上界，不预先解析全部日志；正文第一次读取才解析，后续缓存复用。平台服务提供目录、Task 定位、聊天全文搜索、Task/Conversation 分页阅读，以及祖先平台回复分页阅读。

宿主运行目录设置为0700，保护容器规格文件中的连接信息。每轮使用独立随机凭证，绑定运行中的平台 Task，终态撤销；没有给容器操作者 API Key。项目、日期、截止时间和来源在宿主检查。查询容器不挂载业务项目、聊天库或 Docker socket，继续经过 relay 和代理。

平台活动保持只读；用户可在“更多 → 助手设置”显式接入账号已有 HTTP/SSE MCP。忆屿沿用账号 OAuth。保存先前总结先调用 `read_reply`，再调用真实 MCP 定义的分类/写入工具；操作回复允许空活动引用，引用则必须有本轮检索回执。页面执行详情列出工具完成/失败状态。

保留旧日报及其完整覆盖检查，自动日报不接入外部写入工具；Web/CLI 共用连接设置和请求身份。此阶段通过工具按需阅读持久历史，未宣称接入 SDK 原生会话 resume。平台自身的创建/修改 Task 操作、宿主 stdio MCP 不在本切片。

## 验证证据

- 真实 SDK 在新隔离容器中通过专用测试 relay 和既有模型代理执行：`catalog → search_chats → read_task → 总结`，下一轮 `read_reply → list_categories → create_entry`。
- 模拟忆屿服务收到一次确认写入，保存正文包含上一轮总结原文；复用同 request-id 未再次执行，也未产生第二次写入。两个初始提示均未携带历史聊天正文。
- 真实忆屿完成只读 OAuth 握手、16 个工具的协议核验；独立 SDK 容器成功调用 `get_library_status`。没有读取具体记录，也没有向真实忆屿写入测试内容。模拟写入验收不能冒充真实用户记录保存验收。
- Task/FakeRuntime 和真实 MCP HTTP 回归覆盖无全库预扫描、范围/凭证拒绝、终态撤销、截止后问题编辑和日志追加、连续追问及旧源 Task 清理、待人工回复标记与私密 token 排除，以及准备阶段取消。
- 独立 Spec 与 Standards 审查发现的问题已修复并复核：连接上限、可变 Task 的截止时间、旧日报缓存跨层继承、待答复状态。严格 mypy 检查六个模块通过，四项仓库 guard 通过。

测试明细与容器连续性证据保存在本机 `.scratch/platform-mcp-20261113/`，不提交凭据和运行数据。

## 使用示例

1. 刷新平台助手，选择日期/项目，在设置中确认 `reminis` 已接入。
2. 发送“检索这个项目关于代理问题的聊天，整理已完成和待确认事项”。
3. 看到总结后发送“把上一条总结原文保存到忆屿的工作分类，我确认保存”。目标不明确时先回答助手的澄清。
4. 查看返回的记录 ID 和执行详情。若回执是收件箱 `pending_review`，仍需在忆屿收下，不能当作已入正式记录。

最终发布回归：998 项全部通过，6 条现有测试警告；包含真实 SDK 协议、隔离 Docker、MCP HTTP 与 Chromium。六个模块严格 mypy 及四项仓库 guard 通过。
