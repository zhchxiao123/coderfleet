## 正式实现

1. 固定 SDK `0.2.186` / bundled CLI `2.1.329`；安装器、worker、会话工具和能力 API 保持一致。原服务的 MCP/FastAPI 依赖未升级；旧 Task 的版本信息与原会话仍可读取。
2. 初始输入、文字和原生附件插话统一发送结构化输入帧，按 Task/request 生成原生 UUID。同一请求重试稳定，重复文字的新请求仍独立。持久回执与接受事件记录同一个 UUID，CLI send 同时打印它。
3. 插话显示自己的用户消息、接收时间和处理状态，可定位本轮最终回复；支持多个输入进入同一轮、仅 result 才确认的新输入、输出先于回执、SDK 仅首帧携带归属信息。关联只保留在当前 root turn，result 后清空；子 Agent 事件和下一轮不能借用上一轮回复。
4. SDK 错误和原生中断不会标成正常完成。完全没有原生归属的旧日志或未确认输入明确显示未知；Task 结束、失败、中断与单条输入的处理结果分开。
5. 执行详情默认折叠为当前阶段；普通进度不会展开。实时问题、权限和工具失败自动展开；已完成历史中的中途错误不自动展开。问题与授权关闭后重新汇总根和子 Agent 的等待状态。
6. `thinking.display` 接通 `summarized` / `omitted`，继续经现有共享 SDK 参数入口配置；只展示模型实际返回的内容。没有增加一排输入框按钮。
