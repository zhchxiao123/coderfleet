# SDK 优化后的使用收益与原型

日期：2026-11-20，America/Los_Angeles。

问题：保留项目问答为基础后，SDK 升级和消息关联等优化，怎样转化为用户能直接感受到的收益？

配套：[独立交互原型](coderfleet-sdk-experience-prototype-20261120.html)。这是设计演示，不是已上线页面；所有对话、阶段、检查结果与预算均为合成数据，没有连接模型或生产 API。

## 具体收益与交付范围

| 使用场景 | 建议体验 | 范围 |
| --- | --- | --- |
| 执行中补充“iOS 和 macOS 都要覆盖” | 显示已投递、已纳入本轮、完成或中断；可定位对应回复 | 第一批重点：新 SDK UUID 与产品状态的端到端关联 |
| 想知道任务在忙什么 | 默认一条当前阶段；展开才看工具、子任务和可展示的思考摘要 | 第一批：统一执行详情，保留已做的流式渲染及进度合并 |
| 中断、继续或等待人工回答 | 主发送按钮继续复用；明确本轮是否结束、修改是否保留；问题在原对话回答 | 保留原有基础能力，升级后专项验证状态一致性 |
| 查看结果是否可用 | 改动、实际检查、未验证项分别显示，后续反馈继续进入原会话 | 执行详情中的交付示意；真实证据仍需由实现提供 |
| 全库研究或并行修改 | 阶段和分工可展开；独立工作目录隔离修改，再查看差异 | 后续阶段，原型已经显式标注，不能视为第一批已实现 |

运行时升级的价值主要是改善中断、恢复、排队和长会话可靠性；它本身不会自动产生漂亮界面。没有对速度、费用或成功率作量化承诺。

## 三个布局

- **A：对话优先，推荐。** 项目、会话与对话仍是主结构。执行摘要放在回复中，需要时展开。
- **B：伴随详情。** 右侧固定显示阶段、补充要求、执行范围和预算；适合持续关注较长任务。
- **C：任务工作台。** 工作阶段为主，对话放右侧；用于比较复杂并行任务的布局，普通问答仍可直接进行。

同一页面通过 `?variant=A|B|C` 切换，底部浮动栏支持左右按钮及方向键。用户已确认按此方向推进；首批以 A 为默认落实 SDK 升级、插话归属和执行详情，后续从 B/C 选取有用部分。原型代码仍不直接作为正式实现。

## 可体验交互

1. 在顶部选择普通问答、插话、并行审计、原生提问或交付结果。
2. 输入文字发送，先看到“已投递”，随后演示“已纳入本轮”；点击状态定位这条输入对应的演示回复。
3. 展开执行详情，查看步骤；编辑中的草稿保持原样。
4. 空输入时点击主按钮演示中断；输入文字后同一按钮用于发送。
5. 在原生提问场景选择范围，确认后继续原任务。
6. 查看交付中的示例改动、检查通过和未执行的设备验证；所有检查都标为演示。

## 启动

HTML 可独立离线打开。工具浏览器对 `file://` 导航有限制时，可启动只服务此原型的 loopback 预览：

```bash
rtk proxy python3 .scratch/sdk-experience-prototype-20261120/serve.py
```

终端会打印随机端口 URL，服务只绑定 `127.0.0.1`，不提供其他文件或生产 API。所有演示状态留在浏览器内存，刷新重置。
