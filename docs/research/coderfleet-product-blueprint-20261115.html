Harness 的边界

模型负责调查、规划与整理。宿主服务保存确定性的规则和事实；项目代码在指定执行环境内操作。

隔离的协调 Agent

SDK 工具循环，按需检索 CoderFleet 聊天/Task，调用已授权的外部 MCP。

规划与工具选择
↔
CoderFleet 宿主服务

MCP / API / CLI 共用领域能力：范围校验、调度、状态、幂等、交付和回执。

可追溯的产品事实
经宿主调度 → 项目 Task / Conversation / Workflow → 指定工作区与账号执行 → 交付与证据回流

保留已有模型

Task 是唯一执行原子；Conversation 串行承接反馈；Workflow 管复杂依赖；BoardCard 管目标和验收。

明确缺口

平台 MCP 目前只读。委派要新增范围受限的写能力；并行改同仓库要增加受管工作区，不靠会话分叉冒充文件隔离。

按可用的完整切片推进

按门槛排序，暂不编造工期。点击阶段查看用户收益、复用范围和验收条件。

最高优先 · 先保留基础问答

直接问答，需要时再关联工作

复用项目问答、会话、Task 和 renderer，按需增加卡片、工作详情与待处理入口。

用户得到什么

选项目即可提问、追问或开发；复杂委托才展开交付和验收；原生交互继续可用。

通过什么才进入下一阶段

不建卡片也能完成连续问答；桌面、手机、CLI 项目和会话归属一致；刷新、断线和切换后状态不退化。

让“完成”可审查

结果、验证与反馈成为一等信息

新增轻量交付记录，关联实际版本、产物和检查证据；接受和继续修改都回到原工作。

用户得到什么

直接看改了什么、验证了什么、还有什么没测；不用再从长日志里猜完成度。

验收门槛

新改动不复用旧版本的通过状态；普通日志清理后交付仍可用；执行结束不自动视为接受或发布。

扩展现有按需检索架构

全局对话可以把调查继续推进成工作

在现有只读 MCP 上增加范围受限的委派与状态查询，保留外部操作记录。

用户得到什么

检索聊天 → 整理总结 → 保存忆屿；也可将发现的问题委派给授权项目，再汇总交付。

验收门槛

目标范围明确；网络丢回执不重复委派或保存；工具缺失、未读完和没有结果分别解释。

在写入隔离之后扩大并发

多个工作并行，各自可审查、可汇合

增加受管 worktree/工作目录、基础版本、父子工作关联与合并路径。

用户得到什么

同一项目的不同目标可以独立推进；看清各自改动、依赖、预算和冲突。

验收门槛

并行文件不污染；取消只清理受管资源；冲突可处理；SDK 内部子任务和平台 Task 不混用身份。

把验证过的流程持续使用

自动运行，也有交付与反馈

继续使用 Schedule、Continuation、Workflow，从交付生成周报、项目摘要和外部记录。

用户得到什么

重要变化回来提醒，稳定结果沉淀成带来源、可修订的项目知识；每次运行都可查。

验收门槛

触发去重、范围与时区明确，失败和成本可见；不暗改 agent 创建计划直接生效的现有策略。

首个切片：保留项目问答，再增加交付能力

先验证选项目 → 直接问答 → 连续追问 / 开发 → 历史续聊；再沿原对话按需关联工作，增加交付与检查、验收和继续修改。

05

衡量结果，管理边界

重点应如何判断
产品效果被接受的交付率、每次交付的必要决策和补救操作、到有用结果的时间。先采基线再设数值目标。
真实验证区分模型自述、原始工具输出、平台受管检查和人工/设备验收；证据对应明确版本和环境。
恢复与写入会话、文件工作区、进程接管和外部写入分别恢复；结果未知时可查询，不自动重放副作用。
迁移旧 Task、Conversation、卡片和 session 继续可读可恢复；按完整切片启用，保留回退入口。
明确保留的能力与约束
  • 项目问答是默认基本入口；直接问答和开发不强制建卡片或验收。
  • 账号、认证、容器与代理隔离，CLI / Web 能力对等。
  • 原生插话、中断、提问、历史 Task 控制和高级 SDK 设置。
  • SessionStore、hooks、子 Agent 等已有接入；不把它们重新列成待开发。
  • BoardCard 继续单一引用 Conversation 或 WorkflowRun，自身不执行。
本阶段暂缓的范围

完整 IDE、多租户 SaaS、自己的模型循环、通用插件市场、默认全项目读写、跨供应商无感 session 迁移，以及同时重写前端框架/存储/调度器。

需要在后续 PRD 明确的决定

是否更新现有 North Star；较大目标的卡片与验收模型；自动接受与人工验收边界；是否重开 Schedule 的频率/预算 ADR；何时进入多用户信任模型。对外产品形态还需按实际认证与计费路径核验供应商条件。
