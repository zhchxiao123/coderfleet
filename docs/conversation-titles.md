# 会话标题

新建项目聊天会先显示首条输入的简短名称；服务端随后通过已配置的系统模型提取工作主题。标题会在桌面侧栏、顶部标签、聊天标题和手机页面同步更新，正文与输入草稿保持原位。

## 自动命名

- 桌面、手机与 Telegram `/new` 创建的普通聊天自动启用命名。CLI 可使用 `coderfleet task run "修复历史消息加载时的滚动跳动" --project my-project --auto-title`。
- 主题来自首个明确目标、最近的实质输入，以及已结束 Task 的公开回答。上下文有长度限制，工具输出和思考内容不参与命名。
- `hi`、`继续`等输入会等待后续明确目标；“hi → 排查 OAuth 回调 → 继续”会保留中间的排查目标。已接受的原生补充消息也可以提供主题。
- 主题一旦生成即保持稳定。后续追问可通过菜单主动重新生成标题。
- 人工名称具有优先权。晚到的自动结果和旧 Task 状态回写都通过版本检查，避免覆盖新名称。

系统模型暂未配置、网络错误或输出无效时，原名称继续保留，状态可在会话菜单查看。临时失败最多自动尝试三次，服务重启后继续恢复；达到上限后可手动重试。归档会暂停命名，恢复时保留剩余重试预算。命名通过独立后台队列执行，不占用项目编码 Task。

## 修改已有标题

在桌面侧栏的会话菜单，或手机的会话操作菜单中，选择“重命名”或“重新生成标题”。生成失败时菜单提供重试入口。重新生成是明确替换当前名称的操作，执行期间再次人工改名会使旧自动结果失效。

已有历史会话继续保留原名，包括来源无法确定的旧名称。需要改善某条名称时，单独选择重新生成；系统不会批量猜测哪些历史名称可以覆盖。通过 CLI 指定的 `--new-chain NAME` 也保留明确名称。

CLI 提供相同操作：

```bash
coderfleet task title CONVERSATION_ID
coderfleet task title CONVERSATION_ID --regenerate
coderfleet task title CONVERSATION_ID --name "历史消息加载与滚动修复"
coderfleet task title CONVERSATION_ID --json
```

可在系统设置中配置用于标题和翻译的系统模型。标题接口延续平台操作员认证；公开状态只返回名称、来源、版本和生成状态。
