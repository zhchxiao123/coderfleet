# Agent 工作台改造：第一批可用切片

依据：`docs/research/coderfleet-product-redesign-20261115.md`，以及用户确认“保留原来的项目问答作为最基础能力”。改造基线：`2415967`；之前的日志/图片修复已在 `63e998f` 提交。

## 本批目标

保留默认项目问答，在其上增加可用的工作与待处理入口。复用已有记录，不增加执行引擎，不批量迁移用户会话。此批是阶段 A 的基础切片，不代表整体改造或阶段 B–E 完成。

## 行为与验收

1. 默认仍进入 AI 对话。项目的新建/历史会话、直接问答和开发不要求先建卡片、工作流或验收表；既有 SDK 控制与渲染保持可用。
2. 工作视图从普通 Conversation、独立 Task、现有 BoardCard 与 WorkflowRun 派生。关联卡片丰富原会话，不为同一执行重复创建记录；普通问答完成不自动进入待验收。
3. 待处理视图列出有效的待回答/工具授权、工作流审批、显式待验收卡片和失败/受阻工作。新排队消息不覆盖正在等待回答的 Task；已恢复的旧失败、过期问题和归档记录不继续制造待处理项。
4. 跳转使用明确的原 Task/Conversation/WorkflowRun/卡片引用。不存在或归档的目标明确报错，不回退其他会话。损坏卡片引用仍能在原看板被发现。
5. 从工作视图返回项目问答保留会话；不同会话/项目的未发送文字草稿各自保存，附件不跨会话误带。工作流跳转显示运行面板与正确审批状态。
6. Web 和 CLI 共用分页查询接口；支持项目、运行中、待处理、待验收和受阻筛选，未知项目明确拒绝。只读响应不包含控制/审批令牌或工具输入中的凭据。
7. 手机复用桌面的工作列表与目标解析，通过原手机聊天回答问题；复杂工作流与专题转到相应的原管理视图。默认手机项目列表/问答继续保留。
8. 不重启业务容器、不安装到现有服务、不调用真实模型来验收本批只读视图。界面验证使用隔离本地示例服务；协议/浏览器结果与真实模型验收分别记录。

## 检查方法

- 先以公开 HTTP/CLI 行为验证，再接 UI；测试使用现有 Scheduler + FakeRuntime 和临时工作区。
- Node 行为测试覆盖页面往返、目标定位、桌面/手机草稿归属、失效引用、工作流面板与审批标签；保留全部既有 SDK composer/renderer 回归。
- 隔离浏览器检查默认问答、无卡片会话、草稿往返、工作列表、原生问题入口、390px 手机布局、审批与专题定位。
- 最后运行完整 Python 套件、类型检查与仓库 guards，完成 Standards / Spec 复核后提交。

## 下一批范围

目标/验收点的结构化编辑、从原对话关联工作、版本化交付与验证记录、独立交付面板属于下一批。平台 Agent 写委派、受管 worktree、跨供应商路由与新自动化策略也不由本批隐式启用。
